# Authoritative moving-shell prototype

`src/sim/projectiles.asm` owns 512 pooled 64-byte moving shells. Constants and exported record offsets are in `schemas/combat.inc`; army records remain unchanged, and projectiles do not inflate army counts. `projectile_init` resets pool/counters and finite shell stocks (64 per initially configured armour/artillery entity). `projectile_spawn(source,target)` accepts valid living opposing entity IDs and launches only from an actual shell-capable source. Internal `projectile_launch(source,kind,x,y,z)` validates source, finite target coordinates, ammunition, cadence and capacity. These are authoritative runtime APIs, not accepted client damage claims.

Tank rounds travel directly at 300 m/s. Artillery shells travel horizontally at 180 m/s with gravity 9.81 m/s² and an initial vertical component calculated for a fixed target point. Shots do not home. Cadences are 30/90 fixed ticks; ammunition and cooldown persist per source entity. Depleted stocks do not regenerate. A saturated pool rejects launches, counts dropped requests and preserves existing shells. TTL is 240 ticks; leaving the map expires safely without invalid events.

Each tick sweeps the old/new segment against authored terrain solids and analytic-ground samples, including endpoint ground checks. Eight bisections locate a last clear impact point outside walls. Swept actor contacts use a four-metre approximate body radius and the existing bounded spatial-grid samples. Explosion radius/damage are 18 m/80 for tanks and 35 m/100 for artillery. Blast damage uses three-dimensional distance plus physical LOS, affects living opponents only, and decrements casualty counts once. Aircraft at altitude are not damaged merely because their ground projection lies inside a blast.

Shell contact and blast queries each visit at most nine cells ×24 sampled actors; no shell-to-all-entity loops were introduced. Crowded-cell sampling can miss relevant bodies and blast victims. Actor contact chooses the first intersecting sampled body rather than an exact nearest-mesh collision. There is no penetration, armour-facing model, shrapnel, suppression from blasts, dynamic terrain destruction, reload/resupply or server cosmetic replication implemented by this module alone.

`sim_projectile_count`, `sim_projectile_dropped`, `sim_shell_ammo` and `sim_shell_cooldown` expose metrics/state. Pool records, counts, allocation cursor and per-entity stocks/cooldowns participate in same-build replay hashing. The persistent bounded cosmetic ring `sim_events[256]` uses 32-byte records, `sim_event_sequence` as the latest sequence, `sim_event_count=min(total,256)`, slot `sequence&255`, first sequence1. Kinds are tank launch1, artillery launch2, tank impact3, artillery impact4, vehicle destruction5. `reset_event_ring` clears only cosmetic records/counters and does not change the authoritative checksum. Sequence wrap after UINT32_MAX is not yet a long-running-session protocol migration.

`tests/test_combat.py` verifies delayed physical travel, actual full-world integration, tank/artillery motion, swept wall/ground/actor impacts, opposing-only damage, artillery blast wall occlusion, exactly counted lethal casualties, finite/bounds rejection, saturated-pool preservation, event ring wrap/reset, fixed army membership and repeated replay checksums. The existing fast gate passes. The tactics fixture now gives 64 shells when it deliberately converts an initialized infantry record to armour/artillery; this is test setup, not runtime refilling.

## Player cannon priority and vehicle integration

AI `projectile_spawn` reserves the final32 slots for direct player/internal `projectile_launch`: ordinary army launches refuse once480 shells are active, while player cannons may use all512. Rejected valid ready-to-fire requests increment the drop counter; invalid sources, depleted ammunition and cadence rejection do not count as saturation. The stress fixture fills480 army shells, confirms AI refusal, then fills32 direct launch slots and verifies full-pool preservation. This is bounded prioritization, not increased capacity or a promise that arbitrary external launches cannot exhaust the pool.

Swept actor contact now returns the projected physical contact XYZ rather than exploding at the segment endpoint. A steep-angle fixture verifies that an actual aircraft contact damages the encountered aircraft and emits a finite impact near that actor, not a remote endpoint. Minimum flight time is one fixed tick, preventing short-distance first-tick overshoot.

World initialization resets vehicle state; occupied armour skips autonomous movement and firing, while remaining the same individually counted army entity. Player ticks pass validated full input to the vehicle helper (including connected dead slots so action edges cannot queue across death). Handled boarded/destruction ticks skip infantry movement/rifle/enemy-hit logic. Disconnect and player death detach ownership; destroyed hulls cause the helper's crew death/redeployment path. Vehicle records/private action edges participate in checksums, and the existing player64-byte ABI remains unchanged. ENTER8/EXIT16 are now valid input flags; bit32 remains rejected.

The actual written vehicle module was linked for verification, without stubs. Entire fast gate and focused shell suite pass; a real-world integration fixture verifies board, one movement step per tick, cannon travel hitting a200m opponent, unchanged rifle counters/ammunition, exit/reboard, and hull destruction killing/detaching the driver with30-tick redeployment. The separate vehicle worker owns the module and its exhaustive lifecycle tests/documentation. No network/GPU claim is inferred from this local authoritative test.
