# Source meshes and authored animation in the live renderer

The client loads `content/models/battle.rham` using the NASM RHAM v1 loader. Missing/invalid packs fail startup with a specific message; there is no old block-unit/weapon fallback. The linked pack contains16 high/low source meshes spanning soldier, armor, artillery, aircraft, rifle, bunker, tree and building. Its final SHA256 is `4d8e7faec6ea1fb6c2375cba86aadff8df38326c3f535c6afaeec95681356921`, size11,328,032bytes. Source licensing, provenance, conversion and generated credits belong to the content pipeline/manifest; public code licensing remains the owner's decision.

The GPU pulls source positions, normals and sampled material RGB from one read-only SSBO and interpolates adjacent authored baked frames. Soldier clips come from actual Idle/Walk/Run_Gun/Idle_Shoot actions (46frames total); tank/artillery movement uses10 source frames. Runtime heading and walk/run selection follow observed authoritative position changes. Speed divides displacement by elapsed time since the last position change, so render cadence does not double inferred movement speed. A short hold preserves walking between snapshots. Generation changes baseline the movement/shot caches. Player fire clips use newly observed player shot records; ordinary AI rifle animation does not invent a shot counter. If a tank has only a movement clip, idle freezes its first source frame and interpolation rather than running stationary tracks.

High-detail army models are limited to252 plus at most3 other human bodies, within150m; per-role/side quotas prevent the first allied range from taking every slot. Other living units within800m use their actual reduced source mesh. Far units and tactical views use readable colored triangle markers at their real coordinates. This is a distance/detail budget, not disappearance of authoritative forces. Team tint preserves source material colors and separates allied/enemy sides; humans use cyan. CPU storage is fixed (32768army plus4player cache/instance slots), with no per-frame allocation. The source vertices are uploaded once. Simulation, network authority, terrain height and camera projection remain shared.

The real static rifle model replaces the old HUD weapon rectangles. Cosmetic recoil and authoritative reload fraction move the viewmodel; no authored rifle reload or animated first-person hands are claimed. Humans use the soldier source mesh. Source bunker meshes fit existing obstacle bounding dimensions/base/height; these are coarse collision volumes, not triangle-exact cover. Building meshes mark sites;16 tree placements are decorative and do not imply new gameplay concealment. Aircraft use a real craft mesh, retaining the current authoritative/role altitude convention. This is a sourced low-poly presentation, without new shadows, skeletal transition blending, texture streaming or an art-quality/playtest claim.

RHAM layout:48byte header (magic/version/total size/mesh count/clip count/vec4 count/mesh offset/clip offset/vertex offset),64byte mesh descriptors,16byte clips. Each expanded triangle vertex per source frame has three vec4 records: position, normal, RGB. Mesh descriptors supply role/LOD, vertex/frame counts, base vec4 offset, clip range, scale/radius and XYZ bounds. The loader checks exact file size≤64MiB, descriptor/clip/data ordering/alignment, integer ranges with64bit products, triangle counts, clip frames/semantics/fps, finite scale/bounds and every vertex component. It requires actual high/low army meshes plus the rifle and environment roles before uploading GPU data.
