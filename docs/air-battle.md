# Playable air battle

Run `python3 tools/dev.py run --client --scenario air-battle`.
The ordinary first-person controls apply. The player starts behind allies at3500/2000m, looking toward an encounter containing32aircraft and128ground actors per side. The other7,872actors remain in the full8,192army and use ordinary simulation. Only initial positions and valid flight poses/stores are arranged; subsequent flying, acquisition, attacks, damage, flight breaks, destruction, events and smoke come from production modules. Default scale-open is unchanged. This local scenario is not available with `--connect`; co-op always uses server authority.

The300tick deterministic replay observes65bomb releases,61physical impacts,2,590air gun bursts and84aircraft destructions. These include the full operation, not only the arranged cohort. The12second silent software-GL recording contains360frames and submits all8,192actors without recording-time state writes. Its authentic video and runtime report are retained under ignored `runs/air-battle-demo-final.{mp4,json}`. It is a development demonstration, not a dense-front performance or human spectacle acceptance test.

Fighters bank into interception, fire finite forward-cone gun stores and break after surviving damage. F-111 tactical bombers align actual gravity bomb passes and abort after damage. These use bounded kinematic flight: no full aerodynamic solver, shooter-directed evasion, imminent-projectile avoidance, coordinated wingmen, landing/rearm, moving wing animation or physical wreck debris is claimed. Engine wisps and damage smoke are cosmetic; they do not block LOS. Aircraft pose snapshots remain sparse and can visibly jump.10Hz projectile snapshots can miss short-lived rounds, and the shared512projectile pool can saturate.
