# Restrained bloom

The assembly HDR renderer now runs three fullscreen passes before world tone mapping: half-resolution bright extraction, horizontal Gaussian blur, then vertical Gaussian blur. Two RGBA16F textures alternate; no pass samples its destination. Extraction averages a clamped 2×2 source block and keeps radiance above Rec.709 luminance 1. The normalized nine-sample blur has radius four half-resolution pixels per axis. Bilinear composition adds 0.12 of the blurred radiance before existing exposure, extended Reinhard and display encoding. The shader bounds strength to 0.25. This is a fixed single-scale halo, not a cinematic lens model.

Both textures use linear filtering and clamp-to-edge; odd dimensions round upward. Storage is 8 bytes per pixel per texture: 8,294,400 bytes total at 1920×1080 and 33,177,600 bytes at 3840×2160. Startup dimensions remain fixed under the existing HDR contract. Compilation, link or framebuffer failure rejects HDR initialization; partial resources are released. Shutdown is idempotent.

Fragment texture unit 15 is reserved for bloom. Material units 0–3 remain available, and presentation restores active unit 0 and the full viewport. World rendering uses bloom by default; tactical display colours bypass extraction and composition. HUD rendering follows presentation. `bloom_enabled` and `bloom_strength` are cosmetic globals for development controls; no settings UI is implemented. The module never changes authoritative simulation or network state.

Actual assembled renderer and embedded production shaders pass software GL and hidden Arc A770 GL4.6 pixel controls.
