# Current-frame directional sunlight shadows

The Linux HDR world renderer now builds a 2048×2048 DEPTH_COMPONENT24 sunlight map before colour and actor census. Actual coarse/refined terrain and existing animated low-detail models, props and wrecks cast onto terrain and models. The fixed sunlight matches the existing material direction; ambient and event-flash lighting remain independent. Nine comparison taps use receiver-plane correction and a half-texel bias to avoid coplanar self-shadowing, with a fade at the map edge.

CPU runtime is NASM/SSE2. The camera-centred orthographic region spans ±512 light-space metres with ±1024 depth, snapped to four-metre x/z cells. Private model scratch is stably compacted within 640 horizontal metres, at most 128 casters per descriptor batch and 1024 per frame. Army candidates beyond the radius or budget are rejected before expensive cosmetic pose/support work. Selection follows source order, not a global nearest-caster ranking. Terrain has a separate fixed triangle budget. Depth and colour reuse one animation/motion observation per frame; simulation state is read-only.

`sun_shadows_init` / `shutdown` own the depth texture and framebuffer. `begin` / `end` preserve independent read/draw framebuffer bindings and viewport. `apply` uses direct-state-access uniforms without changing the current program or VAO; texture unit 14 is reserved for the comparison map (bloom owns 15). The map is unbound during depth production to prevent feedback. Caller owns depth-test/write state and must complete a begun pass before starting another. Internal `sun_shadows_enabled` allows paired controls. Tactical and legacy-HDR paths bypass the pass and receivers. The weapon, markers, sky, particles and HUD retain their existing presentation.

Focused tests exercise production NASM resource/matrix/filter/ABI paths, production embedded caster and receiver shaders on software GL and native Arc, and a whole-client paired observer with the original 8192 army. The observer freezes development camera/simulation/cosmetic clocks, stops only after presentation, checks complete source bytes plus the actual full simulation checksum before/after depth, and compares enabled, disabled, repeat and tactical controls. It is not a live multiplayer or artistic acceptance test. Exact reports, failures, executable hashes and frozen checkpoint scopes are recorded in evidence and status.md.

Limitations: one nearby map, no cascades or whole-map shadow coverage; bounded source-order caster admission can omit crowded actors. Existing first-person self/boarded-body exclusions also affect casting. No translucent/particle shadows, event-light occlusion, persistent-fire lighting, quality/accessibility UI, full Windows renderer parity, final art or sustained dense-battle performance acceptance. The full game specification remains open.
