# Bounded combat cosmetics

The first cosmetic slice reads all four authoritative player records. Every third new rifle shot can emit one thin world-space tracer. A64record/32byte fixed pool rotates on saturation; render-time lifetimes are independent of simulation ticks. Generation changes baseline counters, repeated snapshots/render frames emit nothing, and skipped snapshot intervals collapse to one current cosmetic tracer rather than replay old fire. Authority records remain untouched. The tracer represents a cosmetic100m aim direction, not an exact hit point or ballistic trajectory. No impact location is invented from a hit counter.

`python3 tests/test_client_effects.py CLIENT` drives actual held fire on private Xvfb, reads only counters and cosmetic pool state, captures actual pixels, verifies one tracer for three shots, absence of duplicate emission on later frames, and expiry. The driver temporarily pauses only its owned client while recording the screenshot. Software OpenGL rendering validates the path, not target GPU budgets or human visual quality. Screenshot `/tmp/red-horizon-tracer.ppm` is a development artifact. The initial three-shot tracer run passed with136 sampled yellow pixels; the later actual shell build also passed, with exact final results below. These are sampled rendered pixels, not an entity visibility metric.

The combined-arms slice consumes actual impact/destruction events3/4/5 from the shared256-entry ring, using slot `sequence &255`, exact per-record sequence validation, a maximum60tick age and700m viewing-player radius. Overwritten/unreceived records are skipped; cursor advancement prevents repeated packets/render frames from replaying explosions. One hot radial flash (.45s) and one soft smoke puff (2.5s) share the same64slot pool with rifle tracers. Radius is bounded1.5..12m, alpha is restrained, and effects do not write depth or gameplay smoke/cover. Ring reset, skipped sequences and pool replacement are graceful losses of cosmetic detail. This is a small billboard effect, without material debris, dynamic lighting, wreck cover or a high-quality texture claim.

Local solo additionally draws the actual512slot authoritative moving-shell pool, checking its active field. Co-op does not draw invented shell trajectories: only received real launch/impact events are available in this protocol slice. Remaining flash/smoke lifetimes subtract the age from the actual event tick. A delayed packet older than.45s cannot reignite the flash; at most still-live smoke is shown. This is cosmetic aging rather than authority rollback.

## Authoritative armor controls and display

E submits `INPUT_ENTER`; Q submits `INPUT_EXIT` through the same local/UDP intent path. Only the authoritative entity-index mapping and per-player vehicle record choose the armor title, hull health, cannon ammunition/cooldown, amber ammunition bar and reticle. First-person hides the actually boarded army body; the map retains it. A bounded network camera preview preserves the authority's armor eye height. The client never writes vehicle ownership, ammo, health, projectile or event records. Rifle tracers are suppressed for boarded players. Cannon rounds within4m of the camera are cosmetically hidden to prevent near-plane geometry from filling the view; physical travel/collision still executes.

The GUI test uses the real vehicle module and player/world hooks. It positions the human near an existing allied tank, then uses actual E/W/fire/Q inputs. Boarding selected entity12; drive distance exceeded6m; cannon ammunition fell and a genuine tank-launch event appeared while infantry shot count stayed unchanged. The window displayed ARMOR/CANNON/COOLDOWN/HULL; an actual GL cannon-bar pixel was RGB(255,168,51). Q returned the authoritative mapping to-1 and the title to ON FOOT. Screenshot `/tmp/red-horizon-vehicle-hud.ppm` records the view. Existing source/target encounter fixtures do not directly set vehicle ownership, ammunition, events, projectiles or player HP.

This worker's vehicle GUI evidence is local authority. The renderer submits the same intent bits in co-op, but actual graphical co-op boarding requires the integrator's v3 UDP adapter/state848 build and separate integration validation. No network vehicle GUI result is inferred from local testing.
