# Linux recorded PCM mixer and ALSA pump

`src/audio/audio.asm` implements a fixed 128-voice mixer and Linux ALSA playback.
Project-authored runtime logic is NASM; the external platform service is libasound.
Link the client object with `-lasound`.

Client ABI, Linux SysV AMD64:

- `audio_init() -> EAX`: `0` ready, `1` missing/invalid PCM, `2` unavailable ALSA
  device. Call once before the frame loop; call shutdown before another init.
- `audio_shot() -> void`: submit the preloaded rifle sample. Saturation replaces
  the oldest submitted voice using a rotating fixed slot; there are no allocations.
- `audio_update() -> void`: nonblocking pump, at most 800 new frames per call.
  Call at approximately 60 Hz or more. Partial writes and EAGAIN retain pending
  samples; other ALSA errors request native recovery. Call before shutdown.
- `audio_shutdown() -> void`: close device, disable shots, discard pending output.

The module preloads `content/audio/rifle.pcm`: raw signed 16-bit little-endian,
mono, 48 kHz. It rejects empty, odd-length, unreadable, and over-384000-byte files.
The maximum is 192000 samples (four seconds). This raw format has no header:
conversion and rate/channel verification belong to the development content tool.
The integrator owns the recorded source, conversion, and license manifest.
No runtime procedural replacement sound is generated by this module.

`RH_AUDIO_DEVICE` selects an ALSA device; the default is `default`. The `null`
backend is useful for headless development verification. Device absence is
nonfatal and callers can continue the game without playback. Initialization may
load/configure libraries and files; the frame pump itself has no authored
allocation or filesystem operation. There is no audio callback or background
thread in this initial path, and all calls must come from the same frame thread.

Additional verification interfaces: `audio_load(RDI=path) -> EAX` returns zero on
successful preload and one otherwise; invalid preload disables shots.
`audio_mix(RDI=destination int16*, RSI=frames) -> EAX` accepts `0..800` frames,
returns the count, or `-1` for an invalid bound. The caller supplies writable
`frames*2` bytes. `audio_active() -> EAX` reports voices with remaining samples.
These functions preserve SysV nonvolatile registers. Do not preload while mixing.

Mixing sums each active signed16 sample into a signed32 accumulator, advances
independent voice positions, and clamps the final sample to `[-32768,32767]`.
The pool capacity bounds the accumulator. Memory is static: approximately 384 KiB
sample storage, 512 bytes of voice positions, and a 1600-byte output buffer.
There are no pointers into temporary sample storage or dynamic voice allocations.

Verify with the development-only Python driver:

```sh
python3 tests/test_audio.py --nasm nasm
```

On 2026-10-05, Linux `7.2.6-201.nobara.fc44.x86_64`, NASM `2.16.03`, GCC driver
`16.2.1`, the test passed 16 check groups in `0.030358` seconds including assembly
and shared linking. Checks cover silence, overlapping voices with independent
positions, positive/negative clipping, all-voice accumulator bounds, retirement,
128-voice recycling, invalid and maximal PCM sizes, guarded output boundaries,
zero/maximum/oversized mix requests, ALSA null initialization/write/pump/shutdown,
unavailable device, and missing content. Fixtures are synthetic test samples;
this result verifies the mixer and null device integration, not recorded audio
quality or audible output on a physical device.

Limitations: no physical-device capture/listening test yet; no stereo spatial
panning, distance/occlusion, travel delay, virtual emitters, prioritization,
streaming, per-voice gain, fades, effects, or measured callback/device latency.
Hard voice replacement and clipping can be audible under saturation. The fixed
800-frame pump requires adequate scheduling frequency; long client stalls can
underrun. ALSA recovery is implemented, but forced underrun/EAGAIN/partial-write
fault injection is not yet verified. Windows WASAPI remains future work.
