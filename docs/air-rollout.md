# Prospective runway roll admission

`air_final_clear` now requires a clear prospective wheel-braked stopping path on the selected owned runway before retaining airborne final admission. A ground-level obstacle can therefore cause a go-around even when the existing 120-tick descending airborne preview stays above it. The existing approach code releases its lease and resumes staging; this change does not create a grounded aircraft mode.

All CPU runtime is NASM. `air_ground_speed_step` takes role0/1, previous total ground speed0..3.2m/tick, and signed uphill grade within +/-0.02. It returns `max(0, previous - roleBrake - gravity*grade/sqrt(1+grade²))`, with brakes0.012/0.018m/tick² and gravity0.0109 at fixed30Hz. The returned delta includes slope gravity and braking. Wheel braking prevents reversal; malformed role/speed/grade returns -1 and zero outputs. No engine thrust or atmospheric drag is modeled on this prospective ground roll.

`air_rollout_clear` takes the own physical ID, selected base and positive planned touchdown speed up to3.2. It validates the owned available facility through `air_base_goal`. Starting five metres inside the upstream runway edge, it samples terrain height one metre ahead to estimate signed grade, applies the braking actuator, converts total ground speed to horizontal displacement, samples the next actual ground height, and sweeps the existing4m hull between terrain+4.3m endpoints. Every endpoint remains within the selected runway's usable length. It checks the complete path through standstill, bounded at300 steps; unsafe grade, contact or insufficient length returns0, malformed input/source returns-1. Sources and authority remain read-only. No actor scan, allocation, route or lease mutation occurs inside this query.

Production admission uses the declared final target3m/tick. This is a prospective policy path, not a promise that the current aircraft can already achieve that touchdown speed or contact pose. Actual touchdown tolerances, wheel suspension, rollout execution, parking, finite repair/rearm/refueling and relaunch remain to be implemented. The forecast does not include wreck/actor contact, transverse slope, tire slip, aerodynamic braking or throttle. These limitations must be addressed before claiming a full aircraft lifecycle.

UDP50 and the canonical content fingerprint include `air_rollout.inc` version1. Existing packet layouts remain unchanged; peers with older gameplay fingerprints are incompatible. `tests/test_coop.py` reconstructs canonical policy independently.

`tests/test_air_rollout.py` compares3,210 single-step inputs against an independent arithmetic oracle and ten full stopping sequences against independent discrete integration. Native wrappers verify six SysV nonvolatile registers, stack balance and output canaries. Assembled omitted-brake and wrong-gravity controls must fail. Query cases cover all six runways and both roles, positive speed endpoints, malformed IDs/roles/generations/facilities/scalars and malformed authored solids; snapshots verify read-only authority. Initial-only wall fixtures below airborne final compare production with an assembled control that omits only rollout admission. Both sides and roles fly120 genuine public ticks, preserve finite HP/ammunition/generation, satisfy original1mm travel and longitudinal/vertical/roll bounds, and produce deterministic paired traces. This suite establishes prospective admission and go-around behavior, not actual landing or graphics/network/scale performance.
